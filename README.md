# BREAKGLASS

Autonomous red-team security assessment agent designed for safe repository analysis and security hypothesis validation.

> Built for The Agent Harness Hackathon using TrueForge.

---

🚧 **Milestone 4A Complete**: TrueForge Sandboxed Hypothesis Validation Infrastructure implemented.

BREAKGLASS has completed its initial sandboxed hypothesis validation boundary, allowing hypotheses generated by static and LLM reasoning engines to be verified for eligibility, orchestrated deterministically, and run safely within execution boundaries.

---

## Key Principles & Safety Controls

1. **Evidence over Verdicts**: The inspection layer extracts static indicators (e.g. `subprocess_execution_indicator`, `database_query_indicator`). It does **not** declare vulnerabilities or create false alarms.
2. **Safe Execution**: Does not execute repository code, invoke package managers, or run target scripts.
3. **Boundary Enforced**: Skips directory traversal outside the repository root and rejects out-of-bounds symlinks.
4. **Resilient**: Gracefully handles unreadable, malformed, or large files without halting analysis.

---

## Architecture

The intended BREAKGLASS workflow is:

```
Target Repository
      │
      ▼
Repository Ingestion & Path Controls
      │
      ▼
Codebase Inspection (Deterministic Foundation)
      │
      ▼
Repository / Ecosystem / Route / Indicator Map
      │
      ▼
Agent Reasoning Layer (LLM Security Hypotheses)
      │
      ▼
Sandboxed Validation (TrueForge Execution)
      │
      ▼
Evidence + Confidence Score
      │
      ▼
Human Approval Gate
      │
      ▼
Controlled Action
```

## How to Run Inspection

### Programmatic Python API

```python
from breakglass import inspect_repository

# Inspect a local codebase
report = inspect_repository("/path/to/target/repository")

# Access summary metrics
print(f"Total files: {report.repository.total_files}")
print(f"Languages: {report.repository.languages}")
print(f"Frameworks: {report.repository.frameworks}")

# Access security indicators
for indicator in report.security_indicators:
    print(f"[{indicator.category}] {indicator.file}:{indicator.line} -> {indicator.indicator_type}")

# Export structured report to JSON
json_output = report.to_json(indent=2)
```

### Command-Line Interface (CLI)

BREAKGLASS provides a command-line interface to perform end-to-end repository assessment, reasoning, and validation:

```bash
# Basic run: inspect repository statically and generate hypotheses
breakglass /path/to/target/repository

# Run with LLM-assisted reasoning expansion
breakglass /path/to/target/repository --llm

# Run with sandbox validation of eligible hypotheses enabled (using Mock validator)
breakglass /path/to/target/repository --validate

# Run with sandbox validation using TrueForge local subprocess or container sandbox
breakglass /path/to/target/repository --validate --validator local
breakglass /path/to/target/repository --validate --validator container

# Run validation and export structured JSON assessment report to a file
breakglass /path/to/target/repository --validate --output report.json
```

Options:
* `target_path` (positional): Local directory path of the target repository to inspect.
* `--output`, `-o`: Output JSON file path to write the structured assessment report.
* `--llm`: Enable LLM-assisted reasoning using Google Gemini (requires `GEMINI_API_KEY` or `GOOGLE_API_KEY` in environment variables).
* `--validate`: Enable sandbox validation of eligible hypotheses.
* `--validator`: Sandbox validator backend selection (`mock` [default], `local`, `container`, `trueforge`).
* `--max-hypotheses`: Maximum number of hypotheses to validate in a single run (default: 10).
* `--timeout`: Timeout in seconds for validation execution (default: 30.0).
* `--verbose`, `-v`: Enable verbose logging.

### Agent Reasoning (Security Hypothesis Layer)

BREAKGLASS has two reasoning modes:
1. **Deterministic Reasoning:** Fast, offline baseline hypotheses matching static patterns directly.
2. **LLM-assisted Reasoning:** Expands hypotheses by asking an LLM to reason over the structured inspection report, with full validation.

#### Deterministic Reasoning Example

```python
from breakglass import inspect_repository, DeterministicReasoningEngine

# Step 1: Inspect the codebase statically
report = inspect_repository("/path/to/target/repository")

# Step 2: Run the reasoning engine to correlate evidence and generate hypotheses
engine = DeterministicReasoningEngine()
reasoning_report = engine.generate_hypotheses(report)

# Access generated security hypotheses
for hyp in reasoning_report.hypotheses:
    print(f"[{hyp.id}] ({hyp.severity}) {hyp.title}")
    print(f"  Category: {hyp.category}")
    print(f"  Confidence: {hyp.confidence}")
    print(f"  Rationale: {hyp.rationale}")
    print("  Evidence References:")
    for ref in hyp.evidence_references:
        print(f"    - [{ref.type}] {ref.file}:{ref.line} -> {ref.detail}")

# Export reasoning report to JSON
json_output = reasoning_report.to_json(indent=2)
```

#### LLM-assisted Reasoning Example

```python
from breakglass import inspect_repository, DeterministicReasoningEngine, LLMReasoningEngine, MockLLMClient

report = inspect_repository("/path/to/target/repository")
det_report = DeterministicReasoningEngine().generate_hypotheses(report)

# Instantiate LLM Reasoning Engine with an LLM client
# Use MockLLMClient for offline/testing, or a custom LLMClient provider implementation
client = MockLLMClient(response_text='{"hypotheses": []}')
llm_engine = LLMReasoningEngine(client)

# Run LLM-assisted reasoning
llm_report = llm_engine.analyze(report, det_report)
print(f"Validation status: {llm_report.validation_status}")
print(f"Errors: {llm_report.errors}")
```

#### Validation & Safety Controls
* **Untrusted Data Boundary:** Repository data is treated purely as untrusted data. The reasoning layer never executes repository code, scripts, shell commands, or network queries, operating strictly in-memory.
* **Schema Validation:** LLM output is parsed as JSON and validated against a strict schema (verifying required fields, categories, confidence, and severity). Mismatched JSON member types (e.g. non-dictionaries in lists) or provider responses (e.g. None, integer, or list) fail validation cleanly instead of causing crashes.
  * **Strict Field Types:** Validates that string fields are strictly string instances, and that the `line` number attribute is strictly an integer instance (explicitly rejecting float values, strings, lists, or booleans) or null.
* **Evidence Integrity Verification:** Every evidence reference generated by the LLM (files, lines, and types) is independently cross-referenced against the actual inspection report. If the LLM invents or fabricates any evidence, the hypothesis is rejected.
  * **Authoritative Detail Resolution:** The validated evidence details are overwritten with the authoritative inspection details from the report, completely neutralizing fabricated LLM text.
  * **File Reference Validation:** Plain file evidence references must not contain any line numbers.
* **Same-File Correlation Boundary:** The deterministic reasoning layer limits code correlations (subprocess, serialization, database queries) strictly to the same file to prevent repository-wide Cartesian explosions. Unsafe SQL construction is required to trigger SQL Injection hypotheses, ignoring generic ORM or parameterised query indicators.
  * **Proximity Bounding:** Same-file correlations are restricted to evidence elements located within a maximum distance of 50 lines.
  * **Correlation Cap:** Imposes a strict limit of 50 correlations generated per file.
* **Stable Hypothesis IDs:** Hypothesis IDs are generated deterministically using SHA-256 hashes of their canonical serialized identities (sorted keys and complete evidence correlation data) to prevent collisions.
* **Validation Abstraction (Milestone 4A):** Pluggable validation engine orchestrates and executes hypotheses inside boundaries using TrueForge.
  * **Validation States:** Tracks validation results explicitly: `NOT_ATTEMPTED`, `VALIDATED`, `NOT_CONFIRMED`, `SANDBOX_ERROR`, `TIMEOUT`, `INVALID_HYPOTHESIS`, and `PREFLIGHT_ERROR` (for pre-execution adapter configuration errors).
  * **Eligibility Boundary:** Performs strict runtime type and constraint verification on all hypothesis fields. Validates and resolves all evidence references matching authoritative inspection report data, replacing caller-provided strings with report-generated details.
  * **ID & Field Authentication:** Recomputes stable hypothesis IDs at the validation boundary to prevent tampering. Overwrites caller-supplied fields (title, description, severity, confidence, rationale) with authoritative generated data for deterministic hypotheses.
  * **Non-blocking Timeout Execution:** Spawns sandbox validators inside a thread-pool, returning control immediately upon timeout. Note that Python threads cannot be forcibly terminated, so production validator adapters must enforce their own subprocess/container/API execution deadlines.
  * **Execution Safety & Copy Sanitization:** Validator exceptions are caught and wrapped in `SANDBOX_ERROR` states. Sandbox results undergo integrity verification (checking type, invariants, ranges, serializable metadata, and size constraints) and are returned as copy-sanitized new objects.
  * **Sandbox Deferred:** Sandbox execution container setup and human approvals are deferred to subsequent milestones.

### Sandbox Validation (Milestone 4A)

BREAKGLASS orchestrates structured hypothesis validation against sandboxed validation boundaries using TrueForge:

```python
from breakglass import (
    inspect_repository,
    DeterministicReasoningEngine,
    ValidationEngine,
    MockSandboxValidator,
    ValidationConfig
)

# 1. Gather hypotheses from reasoning layers
report = inspect_repository("/path/to/target/repository")
det_report = DeterministicReasoningEngine().generate_hypotheses(report)

# 2. Configure Sandbox Validator and Orchestration Engine
validator = MockSandboxValidator()  # Or TrueForgeSandboxValidator(api_key="...")
config = ValidationConfig(timeout_seconds=30.0, max_hypotheses_per_run=10)
engine = ValidationEngine(validator, config)

# 3. Perform Sandboxed Validation
results = engine.validate_hypotheses(det_report.hypotheses, report)

for res in results:
    print(f"Hypothesis: {res.hypothesis_id}")
    print(f"  Status: {res.status}")
    print(f"  Attempted: {res.attempted}")
    print(f"  Confirmed: {res.confirmed}")
    print(f"  Duration: {res.duration} seconds")
```
