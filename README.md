# BREAKGLASS

Autonomous red-team security assessment agent designed for safe repository analysis and security hypothesis validation.

> Built for The Agent Harness Hackathon using TrueForge.

---

## Status

🚧 **Milestone 3 Complete**: LLM-assisted Security Reasoning implemented.

BREAKGLASS can statically inspect unfamiliar software repositories, generate baseline deterministic hypotheses, and leverage an LLM-assisted reasoning layer to expand and correlate hypotheses with strict schema and evidence validation.

---

## Key Principles & Safety Controls

1. **Evidence over Verdicts**: The inspection layer extracts static indicators (e.g. `subprocess_execution_indicator`, `database_query_indicator`). It does **not** declare vulnerabilities or create false alarms.
2. **Safe Execution**: Does not execute repository code, invoke package managers, or run target scripts.
3. **Boundary Enforced**: Skips directory traversal outside the repository root and rejects out-of-bounds symlinks.
4. **Resilient**: Gracefully handles unreadable, malformed, or large files without halting analysis.

---

## Architecture

The intended BREAKGLASS workflow is:

```
Target Repository
      │
      ▼
Repository Ingestion & Path Controls
      │
      ▼
Codebase Inspection (Deterministic Foundation)
      │
      ▼
Repository / Ecosystem / Route / Indicator Map
      │
      ▼
Agent Reasoning Layer (LLM Security Hypotheses)
      │
      ▼
Sandboxed Validation (TrueForge Execution)
      │
      ▼
Evidence + Confidence Score
      │
      ▼
Human Approval Gate
      │
      ▼
Controlled Action
```

## How to Run Inspection

### Programmatic Python API

```python
from breakglass import inspect_repository

# Inspect a local codebase
report = inspect_repository("/path/to/target/repository")

# Access summary metrics
print(f"Total files: {report.repository.total_files}")
print(f"Languages: {report.repository.languages}")
print(f"Frameworks: {report.repository.frameworks}")

# Access security indicators
for indicator in report.security_indicators:
    print(f"[{indicator.category}] {indicator.file}:{indicator.line} -> {indicator.indicator_type}")

# Export structured report to JSON
json_output = report.to_json(indent=2)
```

### Agent Reasoning (Security Hypothesis Layer)

BREAKGLASS has two reasoning modes:
1. **Deterministic Reasoning:** Fast, offline baseline hypotheses matching static patterns directly.
2. **LLM-assisted Reasoning:** Expands hypotheses by asking an LLM to reason over the structured inspection report, with full validation.

#### Deterministic Reasoning Example

```python
from breakglass import inspect_repository, DeterministicReasoningEngine

# Step 1: Inspect the codebase statically
report = inspect_repository("/path/to/target/repository")

# Step 2: Run the reasoning engine to correlate evidence and generate hypotheses
engine = DeterministicReasoningEngine()
reasoning_report = engine.generate_hypotheses(report)

# Access generated security hypotheses
for hyp in reasoning_report.hypotheses:
    print(f"[{hyp.id}] ({hyp.severity}) {hyp.title}")
    print(f"  Category: {hyp.category}")
    print(f"  Confidence: {hyp.confidence}")
    print(f"  Rationale: {hyp.rationale}")
    print("  Evidence References:")
    for ref in hyp.evidence_references:
        print(f"    - [{ref.type}] {ref.file}:{ref.line} -> {ref.detail}")

# Export reasoning report to JSON
json_output = reasoning_report.to_json(indent=2)
```

#### LLM-assisted Reasoning Example

```python
from breakglass import inspect_repository, DeterministicReasoningEngine, LLMReasoningEngine, MockLLMClient

report = inspect_repository("/path/to/target/repository")
det_report = DeterministicReasoningEngine().generate_hypotheses(report)

# Instantiate LLM Reasoning Engine with an LLM client
# Use MockLLMClient for offline/testing, or a custom LLMClient provider implementation
client = MockLLMClient(response_text='{"hypotheses": []}')
llm_engine = LLMReasoningEngine(client)

# Run LLM-assisted reasoning
llm_report = llm_engine.analyze(report, det_report)
print(f"Validation status: {llm_report.validation_status}")
print(f"Errors: {llm_report.errors}")
```

#### Validation & Safety Controls
* **Untrusted Data Boundary:** Repository data is treated purely as untrusted data. The reasoning layer never executes repository code, scripts, shell commands, or network queries, operating strictly in-memory.
* **Schema Validation:** LLM output is parsed as JSON and validated against a strict schema (verifying required fields, categories, confidence, and severity). Mismatched JSON member types (e.g. non-dictionaries in lists) fail validation cleanly instead of causing crashes.
* **Evidence Integrity Verification:** Every evidence reference generated by the LLM (files, lines, and types) is independently cross-referenced against the actual inspection report. If the LLM invents or fabricates any evidence, the hypothesis is rejected.
  * **Authoritative Detail Resolution:** The validated evidence details are overwritten with the authoritative inspection details from the report, completely neutralizing fabricated LLM text.
  * **File Reference Validation:** Plain file evidence references must not contain any line numbers.
* **Same-File Correlation Boundary:** The deterministic reasoning layer limits code correlations (subprocess, serialization, database queries) strictly to the same file to prevent repository-wide Cartesian explosions. Unsafe SQL construction is required to trigger SQL Injection hypotheses, ignoring generic ORM or parameterised query indicators.
* **Stable Hypothesis IDs:** Hypothesis IDs are generated deterministically using SHA-256 hashes of their canonical evidence identities to prevent collisions.
* **Validation Deferred:** Sandbox verification of hypotheses (TrueForge validation) is intentionally deferred to Milestone 4.
